# code-quality.md 
기준 : 좋은 코드 = 변경하기 쉬운 코드(Toss Fronted Fundamentals)

## 가독성 
- 동시에 실행되지 않는 분기는 별도 컴포넌트로 분리 
- 페이지에 구현 상세 노출 금지(인증 확인은 Guard로 감싸기)
- 숫자 리터럴은 의미 있는 상수로(ex. ANIMATION_DELAY_MS)
- 단순한 조건은 펼처서 위에서 아래로 읽히게 
- 삼항 연산자 중첩 금지 -> if 문으로 

## 예측 가능성 
- 이름, 파라미터, 반환 타입으로 예측 안되는 동작(로깅, 부수효과) 금지 

## 응집도 
- 비슷하다는 이유만으로 공통화 금지 
- 폼 : 필드 간 의존성 있으면 폼 단위, 독립 검증이면 필드 단위 

## 결합도 
- 비슷하다는 이유만으로 공통화 금지 
- 페이지마다 달라질 여지가 있으면 중복 허용
